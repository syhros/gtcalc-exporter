# Pack Extract

Repository: [syhros/gtcalc-exporter](https://github.com/syhros/gtcalc-exporter). The mod itself is called Pack Extract (mod id `packextract`, command `/packextract`).

A Minecraft mod that exports everything in a modpack: every item and its variants, every fluid, an image of each, the ore dictionary, and the recipes, including GregTech recipes with their chanced outputs. It writes plain JSON and CSV that a website such as [gtcalc.app](https://gtcalc.app) can load.

The first version targets **Minecraft 1.7.10 with Forge**, which covers GT New Horizons.

## Why another exporter

NEI dumps and RecEx miss things gtcalc needs:

- **Variants NEI hides.** GregTech hides shapes such as impure, purified and crushed dusts from NEI. Pack Extract collects items from four places (every item's sub-items, NEI's list, the ore dictionary, and every item any recipe uses), so those variants appear with their own images.
- **Fluids.** Every registered fluid gets its own image, drawn from its texture and tinted with its colour, the same way the game draws it.
- **Images match the game.** Icons are rendered by Minecraft's own item renderer, so layered GregTech icons, 3D blocks and mods' custom renderers look as they do in your inventory.
- **Chances.** GregTech output chances (and input and fluid chances where the GT version has them) are part of each recipe.

## Use it

1. Put `packextract-<version>.jar` in the instance's `mods` folder. It is client-side only; servers do not need it.
2. Start the game and join any world (single player is fine). Joining a world lets NEI load its item list, which adds a few variants.
3. Type `/packextract` in chat. A progress screen shows each step. Press Esc to cancel.
4. When it finishes, click **Open folder**.

`/packextract noimages` skips the images, which is much faster when you only need recipe changes.

On GT New Horizons, expect well over 100,000 images. The image step takes the longest; the rest takes a minute or two.

## Output

Everything goes to `<instance>/.minecraft/pack-extract/<pack name>-<date>/`:

| File | What it holds |
|---|---|
| `manifest.json` | Pack name, date, Minecraft version, every mod with its version, counts, time per step |
| `items.json`, `items.csv` | Every item variant |
| `fluids.json`, `fluids.csv` | Every fluid |
| `images/items/*.png`, `images/fluids/*.png` | One transparent PNG per item and fluid (64 px by default) |
| `oredict.json` | Ore dictionary name → item ids |
| `recipes/crafting.json` | Crafting table recipes |
| `recipes/smelting.json` | Furnace recipes |
| `recipes/gregtech.json` | Every GregTech 5 recipe, one object per recipe |
| `recipes/gregtech-maps.json` | GregTech recipe maps: id, display name, recipe count |
| `errors.log` | Anything that could not be read or drawn, with the reason |

### Ids

An item id is `registryName:meta`, for example `minecraft:log:0` (Oak Wood) or `gregtech:gt.metaitem.01:4032` (Purified Pile of Iron Dust). Items that carry NBT get a hash of it: `minecraft:potion:8193#1a2b3c4d`; the full NBT is in the item's `nbt` field. A fluid id is its Forge name, such as `water` or `molten.iron`.

Image file names come from the id (`gregtech_gt.metaitem.01_4032.png`), but always use the `image` field to find an item's picture.

### items.json

One entry (example):

```json
{
  "id": "gregtech:gt.metaitem.01:4032",
  "registryName": "gregtech:gt.metaitem.01",
  "mod": "gregtech",
  "meta": 4032,
  "name": "Purified Pile of Iron Dust",
  "unlocalizedName": "gt.metaitem.01.4032",
  "isBlock": false,
  "oreDict": ["dustPureIron"],
  "image": "images/items/gregtech_gt.metaitem.01_4032.png",
  "sources": ["registry", "oredict", "recipe"]
}
```

`sources` says where the item was found (`registry`, `nei`, `oredict`, `fluid-container`, `recipe`). `imageBlank: true` marks an icon that rendered fully transparent; `imageError` gives the reason when it could not be drawn.

### fluids.json

One entry (example; values vary by fluid):

```json
{
  "id": "molten.iron",
  "name": "Molten Iron",
  "color": "#c8c8c8",
  "temperature": 1811,
  "density": 1000,
  "viscosity": 1000,
  "luminosity": 0,
  "gaseous": false,
  "texture": "gregtech:fluids/fluid.molten.autogenerated",
  "containers": [{ "filled": "gregtech:gt.metaitem.01:...", "empty": "IC2:itemCellEmpty:0", "amount": 144 }],
  "image": "images/fluids/molten.iron.png"
}
```

### Recipe ingredients

Every input and output in every recipe file has one of these shapes:

```json
{ "item": "minecraft:log:0", "amount": 1 }
{ "item": "minecraft:log:*", "amount": 1, "anyOf": ["minecraft:log:0", "minecraft:log:1", "..."] }
{ "ore": "plankWood", "amount": 1, "anyOf": ["minecraft:planks:0", "..."] }
{ "anyOf": ["...", "..."], "amount": 1 }
{ "fluid": "molten.iron", "amount": 144 }
```

Optional fields: `"chance": 0.25` (0 to 1; missing means always) and `"consumed": false` (for example GregTech programmed circuits). `:*` means "any variant of this item" and `anyOf` lists the variants. An empty crafting grid slot is `null`.

### Recipes

`recipes/crafting.json`:

```json
{ "type": "shaped", "width": 3, "height": 3, "inputs": [9 slots, row by row], "output": {...}, "class": "..." }
{ "type": "shapeless", "inputs": [...], "output": {...}, "class": "..." }
{ "type": "special", "class": "...", "output": {...} }
```

`special` is a mod's own recipe type whose inputs cannot be read in a standard way (armour dyeing, map cloning and so on).

`recipes/smelting.json`: `{ "input": {...}, "output": {...}, "experience": 0.7 }`.

`recipes/gregtech.json`, one entry (example):

```json
{
  "map": "gt.recipe.macerator",
  "index": 120,
  "inputs": [{ "item": "gregtech:gt.metaitem.01:5032", "amount": 1 }],
  "outputs": [
    { "item": "gregtech:gt.metaitem.01:3032", "amount": 1 },
    { "item": "gregtech:gt.metaitem.01:3035", "amount": 1, "chance": 0.1 }
  ],
  "fluidInputs": [],
  "fluidOutputs": [],
  "eut": 2,
  "duration": 400,
  "specialValue": 0,
  "enabled": true,
  "hidden": false,
  "fake": false,
  "metadata": { "...": 0 }
}
```

`eut` is EU per tick and `duration` is in ticks. `specialValue` and `metadata` carry map-specific values such as blast furnace heat. `hidden` and `fake` recipes are ones GregTech itself does not show or run (for example assembly line previews); filter them as you need. `recipes/gregtech-maps.json` gives each map's display name, such as "Pulverization".

## Configuration

`config/packextract.cfg`:

| Setting | Default | What it does |
|---|---|---|
| `imageSize` | 64 | Image width and height in pixels (16-512) |
| `images` | true | Draw item and fluid images |
| `neiItems` | true | Also use NEI's item list |
| `outputDir` | `pack-extract` | Output folder, relative to the instance folder or absolute |
| `packName` | (instance folder name) | Name for the export folder and manifest |
| `frameBudgetMillis` | 40 | Work done per frame; higher is faster, the progress screen updates less often |
| `exportOnMainMenu` | false | Export as soon as the main menu opens, without joining a world |
| `quitAfterMainMenuExport` | false | Close the game after that export |

For scripted exports you can also set `PACKEXTRACT_AUTO=1`, `PACKEXTRACT_QUIT=1`, `PACKEXTRACT_OUT=<folder>` and `PACKEXTRACT_IMAGE_SIZE=<px>` as environment variables, or the same as `-Dpackextract.auto=true` and so on.

## Limits

- **Recipe types.** Crafting, furnace and GregTech 5 recipe maps are exported (in GTNH that includes GT++, BartWorks, GoodGenerator and the other addons that register GT recipe maps). Other mods' own machines (Thaumcraft, Botania and so on) are not exported yet.
- **Minecraft versions.** Only 1.7.10. Newer packs (GregTech CEu on 1.12.2 or 1.20.1) need a separate build of the mod.
- **Main-menu exports.** NEI only builds its item list after you join a world, so a main-menu export skips the few variants that only NEI generates.

## Building

```
./gradlew build          # jar in build/libs
./gradlew runClient      # dev client with NEI
./gradlew runClient -PdevGregTech=true   # dev client with NEI and GregTech 5
```

GitHub Actions builds the jar, runs the unit tests, then starts a real client with NEI, and again with GregTech 5, exports from the main menu and checks the output. That check covers impure and purified iron dust with images, molten iron, chanced macerator outputs, and every item a GregTech recipe uses being listed. A contact sheet of sample images from each run is pushed to the `ci-screenshots-vanilla` and `ci-screenshots-gregtech` branches.
